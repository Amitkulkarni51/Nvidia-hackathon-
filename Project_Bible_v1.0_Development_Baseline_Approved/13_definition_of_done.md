# 13 — DEFINITION OF DONE

A feature is DONE only when all applicable items are satisfied.

## Development
- [ ] Implements the approved requirement.
- [ ] Does not add unapproved behavior.
- [ ] Respects module ownership.
- [ ] Reuses existing architecture/components where appropriate.

## Integration
- [ ] API contract respected.
- [ ] Database contract respected.
- [ ] No unintended changes to another module.
- [ ] Existing functionality still works.

## Quality
- [ ] Tests/checks pass.
- [ ] Error/loading/empty states handled.
- [ ] No secrets committed.
- [ ] Documentation updated where necessary.

## Git
- [ ] Work is on the correct feature branch.
- [ ] Commit is focused.
- [ ] Pull request explains what changed.
- [ ] Integration owner reviews shared-file changes.
